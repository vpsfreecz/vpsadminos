# Linux 6.12.48 livepatch releases

This page covers livepatches built from the final system configuration's Linux
6.12.48 package. Each configuration supplies the kernel source, development
tree, config and toolchain used by its livepatch producer.

## Eligibility

- **Configured kernel:** the final configuration's vpsAdminOS Linux 6.12.48
  package and its matching producer inputs
- **Eligible running kernels:** not yet established; matching the version string
  alone does not prove code or ABI compatibility
- **Native-fixed recovery coverage:** not yet established; Linux 6.12.117
  contains the source correction, but no operator recovery image is approved by
  this release
- **Supported mixed versions:** not yet established
- **Maximum qualified stack depth:** not yet established
- **Boot loading:** `services.live-patches.loadOnBoot`, default `true`
- **Live deployment loading:** `services.live-patches.loadOnSwitch`, default
  `false`

Do not activate this preventive livepatch on a boot that has already hit the
target failure, has an unexplained Oops, or is otherwise unreliable. Follow the
recovery section instead.

## Release `6.12.48.1`

### Identity and provenance

- **Release:** `6.12.48.1`
- **Payload revision:** 1
- **Predecessor:** native 6.12.48
- **Mode:** additive, `replace=0`
- **Source commit:**
  `gregkh/linux@1a5a227bca6a8a9f9d31230697aeb84c62a21da6`
- **Mainline commit:**
  `35ff1a7a7e3835c3e974bc5c45d335897564ceae`
- **CVEs:** `CVE-2026-99362`
- **Prerequisites:** none

### Backport selection and provenance

- **Selected source:** stable Linux commit
  `1a5a227bca6a8a9f9d31230697aeb84c62a21da6`
- **Source release and status:** stable correction first released in Linux
  6.12.117, backported from mainline commit
  `35ff1a7a7e3835c3e974bc5c45d335897564ceae`
- **Prerequisites:** none
- **Source-review conclusion:** the selected commit adds reply-size preflight
  to `nfsd4_sequence()` before reply-buffer restriction and slot acceptance;
  it leaves session representation, locking and the NFS wire format unchanged
- **Target-applicability conclusion:** the pinned vpsAdminOS 6.12.48 source has
  the vulnerable control flow, and the canonical stable patch applies to it
  without fuzz
- **Emitted semantic closure:** one `nfsd:nfsd4_sequence@0`
  replacement, 13 pinned symbol imports and the
  `.klp.rela.nfsd..text` and `.klp.rela.vmlinux..text` relocation sections
- **Accepted selection evidence:** stable and mainline provenance, exact target
  source review and zero-fuzz application

Backport selection establishes source applicability. It does not establish
artifact identity, livepatch transition safety or rollout eligibility.

### Fixes and emitted closure

| Fix ID | Prevention or correction | Patch IDs | Affected object/functions | Oracle IDs |
| --- | --- | --- | --- | --- |
| `nfsd-sequence-reply-preflight` | reject an undersized negotiated SEQUENCE reply before accepting its session slot | `nfsd-sequence-reply-preflight` | `nfsd:nfsd4_sequence@0` | `nfsd-sequence-operation-safety` |

The configured kernel builds NFSD and RPCSEC GSS as modules. The batch targets
`vmlinux` for the established release-level framework,
`fs/nfsd/nfsd.ko` for the semantic replacement and
`net/sunrpc/auth_gss/auth_rpcgss.ko` as the required provider of symbols
imported by NFSD. No replacement is expected in `auth_rpcgss`. Exact artifact
inspection confirmed the pinned replacement, imports, symbol position and
relocation sections. The configured-target build changed only `nfsd.ko` and the
framework's `vmlinux` object; it emitted no replacement for `auth_rpcgss`.

### Livepatch-safety qualification

The configured-target module built and passed strict artifact inspection, but
the release remains unqualified. No captured realization, transition campaign,
ordinary NFSv4.1 operation result, aging result or compatibility result for an
older boot with newer userspace is accepted yet.

Qualification requires the generic lifecycle, busy-transition,
aged-transition and failure/recovery profiles on AMD and Intel/KVM. The
`nfsd-sequence-operation-safety` profile runs on AMD and keeps an ordinary
NFSv4.1 loopback workload active through forward and reverse transitions. It
tests operation safety and data integrity; it does not reproduce the flaw or
compare against a native-fixed kernel.

No safe natural held-frame point is established, and held-frame proof is not a
release gate. Normal convergence must not depend on forcing a transition,
unloading NFSD or stopping user workloads.

### Activation

Release 6.12.48.1 is unavailable for activation until the configured artifact
is captured, the required qualification is accepted and rollout is separately
approved. Source inclusion and a successful build do not grant rollout
permission.

With `services.live-patches.enable = true`, boot loading defaults to enabled and
live deployment loading defaults to disabled. Set both
`services.live-patches.loadOnBoot` and
`services.live-patches.loadOnSwitch` to `false` while loading must remain
manual. See the [automatic-loading policy](process.md#automatic-loading) for
the four policy combinations and action boundaries.

For a future approved manual activation, require the exact qualified healthy
native starting state and a manager inventory without an old or unknown module.
Run `live-patches load 1` once and wait for normal convergence. Require
`enabled=1`, `transition=0`, `replace=0`, the expected published release and
passing NFS operation, integrity and health checks before returning the node to
service. Bare `live-patches load` loads every configured batch in order.

The retired cumulative legacy module is not a predecessor of this numbered
release. A boot with that module loaded is ineligible for this activation; use
the generation that owns the old module and its established recovery procedure.
Do not infer native state from `uname -r`, because both modules can publish the
same `.1` release suffix.

### Rollback

Reversal remains unavailable until forward and reverse transitions are
qualified. After separate approval, `live-patches unload 1` may disable and
remove only the active tip. Require reverse convergence, module removal, native
release state and passing NFS operation, integrity and health checks. Reversal
restores the vulnerable native implementation; it is an operational rollback,
not a security fix.

Disabling automatic loading does not unload an active module. Configuration
rollback does not restore kernel state. Restore a generation that configures the
complete loaded stack before managed removal. Never force a transition or module
removal.

### Recovery

This livepatch is preventive. It cannot repair a reply-cache overwrite,
previously accepted request, uncertain NFS session, application state or
filesystem state.

If a boot has hit the target failure, an unexplained Oops or a related workload
failure, fail over or fence it according to the service procedure. Reboot into
an approved native-fixed generation and reconcile uncertain operations before
returning it to service. Linux 6.12.117 contains the source correction, but this
page does not approve a particular kernel image or deployment.
