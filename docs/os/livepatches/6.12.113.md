# Linux 6.12.113 livepatch releases

This page covers livepatches built for the exact configured Linux 6.12.113
target. Same-version kernel builds are not interchangeable.

## Eligibility

- **Eligible boot identity:** the configured vpsAdminOS Linux 6.12.113 package
  whose running image and extracted ELF notes match the approved release
  capture
- **Native-fixed recovery coverage:** not yet established; Linux 6.12.117
  source contains the complete fix, but source inclusion does not qualify it as
  an operator recovery target
- **Supported mixed versions:** native 6.12.113 and release 6.12.113.1 within
  one boot epoch, after qualification and rollout approval
- **Maximum qualified stack depth:** one; qualification is pending
- **Boot autoload:** disabled

Do not activate this preventive livepatch on a boot that has already hit the
target failure, has an unexplained Oops, or is otherwise unreliable. Follow the
recovery section instead.

## Release `6.12.113.1`

### Identity and provenance

- **Release:** `6.12.113.1`
- **Payload revision:** 1
- **Predecessor:** native 6.12.113
- **Mode:** additive, `replace=0`
- **Source commit:** `vpsfreecz/linux@02beaa9040c47f489991bac14c0bdc00b7a737c9`
- **Provenance status:** downstream only
- **CVEs:** none assigned
- **Prerequisites:** none
- **Boot autoload:** disabled

The patch prevents NFS server sysfs callbacks from outliving the RPC client
state they access. It does not change the sysfs ABI or NFS wire protocol.

### Backport selection and provenance

- **Selected source:**
  `vpsfreecz/linux@02beaa9040c47f489991bac14c0bdc00b7a737c9`
- **Source release and status:** downstream-only v2 change; no upstream or
  stable commit is assigned
- **Prerequisites:** none
- **Source-review conclusion:** the isolated change drains server sysfs before
  client release, retains the NFSv2/v3 client reference through common teardown,
  and ignores unavailable main RPC clients without adding adjacent NLM changes
- **Target-applicability conclusion:** Linux 6.12.113 has the affected client
  lifetime, while the reviewed Linux 6.12.117 source contains the complete
  selected correction
- **Expected emitted semantic closure:**
  `vmlinux:nfs_free_server@0`, `vmlinux:nfs_init_server.isra.0@1`, and
  `vmlinux:shutdown_store@1`
- **Accepted selection evidence:** reviewed downstream history, source analysis
  and exact native-kernel validation of the affected and corrected source paths

### Fixes and emitted closure

| Fix ID | Prevention or correction | Patch IDs | Affected object/functions | Oracle IDs |
| --- | --- | --- | --- | --- |
| `nfs-sysfs-client-lifetime` | drain server sysfs callbacks before releasing NFS client state | `nfs-drain-server-sysfs-before-client-release` | `vmlinux:nfs_free_server@0`, `vmlinux:nfs_init_server.isra.0@1`, `vmlinux:shutdown_store@1` | `nfs-client-operation-safety` |

The source changes `nfs_init_server()` and `nfs_free_server()` in
`fs/nfs/client.o`, plus the static `shutdown_client()` helper in
`fs/nfs/sysfs.o`. The configured compiler emits the replacement closure shown
above: it clones `nfs_init_server()`, inlines `shutdown_client()` into
`shutdown_store()`, and retains `nfs_free_server()` under its source name.

### Livepatch-safety qualification

- **Catalog and producer inspection:** the configured-target build and its
  module, manifest, inspection and closure evidence are accepted; final-head
  capture is pending
- **AMD lifecycle, busy operation and failure/recovery:** pending
- **Intel/KVM lifecycle, busy operation and failure/recovery:** pending
- **Held-frame proof:** not required; none of the emitted replacements has a
  reviewed natural sleepable hold point, so the release does not add a
  synthetic hold
- **Every active fix-local profile:**
  `nfs-client-operation-safety` on AMD and Intel/KVM is pending
- **Whole-stack forward/reverse:** pending for the native to 6.12.113.1 set
- **Fatal kernel-noise and workload-health gate:** pending
- **Unsupported or blocked rows:** none; all eight rows must pass before rollout

The six generic rows cover lifecycle, busy transition and failure/recovery on
AMD and Intel/KVM without importing or running the NFS adapter. Two dedicated
rows alone run the ordinary NFS operation and integrity adapter. Every row uses
the same captured module and exact target. The qualification does not reproduce
the original race or compare a native-fixed kernel.

### Activation

Activation is blocked until the qualification status above is accepted and a
rollout is approved. For an approved rollout:

1. Require a healthy native 6.12.113 boot whose image and ELF notes match the
   approved capture. Confirm `live-patches status` and `live-patches list` show
   no active numbered release.
2. Confirm the captured module, manifest, inspection and closure still match
   the approved realization.
3. Quiesce NFS mount creation, final unmount and writes to NFS `shutdown`
   attributes. Keep established I/O bounded and monitored.
4. Run `live-patches load` once. Require `enabled=1`, `transition=0`,
   `replace=0` and `uname -r` equal to `6.12.113.1`.
5. Run every active safety check, including NFS data-integrity and continued-I/O
   checks. Stop on a mismatch, timeout, workload regression or kernel warning.

Never force a transition or toggle the patch repeatedly.

### Rollback

Reversal is supported only after qualification and rollout approval. Keep the
same NFS creation, final-unmount and shutdown-sysfs quiescence, then run
`live-patches unload` once. Require reverse convergence, removal of the module
and its metadata, and `uname -r` equal to native `6.12.113`. Recheck existing
and fresh serial NFS operation and data integrity. Do not force removal if
reverse convergence is incomplete.

### Recovery

This livepatch is preventive. It cannot repair an already-freed client,
interrupted shutdown work, uncertain RPC/NFS state, application state or
filesystem state.

If a boot has already hit the failure or an unexplained Oops, fail over or
fence it according to the service procedure. Reboot into an approved
native-fixed generation and reconcile uncertain operations before returning the
node to service. Linux 6.12.117 contains the v2 source fix, but it is not an
approved recovery generation until its operator qualification is recorded.
